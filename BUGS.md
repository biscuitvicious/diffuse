# diffuse — known bugs

Confirmed defects awaiting a fix, grouped by subsystem. Checked items are resolved.

## 1. Execution context and CLI

- [x] **Silent empty output when git fails to resolve the input range**: Running `diffuse -p <range>` (or any mode that shells out to `git diff`) with unknown revisions prints nothing — 4 bytes (`\x1b[0m`) on stdout, nothing on stderr — and exits 0. Repro: `diffuse -p f7fa5c3..9b06db9` outside the repository those commits belong to (e.g. submodule SHAs from the main repo); compare with `git diff f7fa5c3..9b06db9`, which correctly reports `fatal: ambiguous argument ... unknown revision or path not in the working tree`. Expected: surface git's stderr and exit non-zero instead of rendering an empty diff. (See **Use ariadne for CLI error reporting** in `TODO.md` §7.)
- [x] **Headless PTY / unresponsive terminal causes unhandled cursor query timeout**: When diffuse is invoked in an environment where `is_terminal()` returns true (such as a headless PTY or automated test runner without an active terminal emulator) and neither `--pager` nor `--no-tui` is specified, diffuse attempts to launch the interactive TUI. During `TerminalGuard::enter()`, Ratatui queries the hardware cursor position (`ESC [ 6 n`). Because no terminal emulator responds, Crossterm times out after 2 seconds with `The cursor position could not be read within a normal duration` and exits with an unhandled `io::Error`. Expected: `diffuse` should catch terminal initialization failure and gracefully fall back to the one-shot pager / CLI renderer instead of crashing.

## 2. Review notes

- [ ] **`notes add` silently ignores `--diff` / `--old-dir` / `--new-dir`**: These flags are advertised in `diffuse notes add --help` under "Repository & Input" (inherited from the shared `Args`), but `notes_cli::add::handle_add` never reads them — it always loads the reviewed content via `load_git_repo` when inside a work tree, and otherwise falls back to raw working-tree file content. The only diff consulted anywhere under `notes_cli/` is `git_res.diff`. Repro: `diffuse notes add --diff <patch> --old-dir <o> --new-dir <n> <file> --new <range> -m <msg>` outside a work tree ignores the patch and snapshots. Expected: either honour the file-based review input in the add flow (provisional rows from the given snapshots, pipeline over the given diff) or stop advertising the flags on the `notes` subcommands.
