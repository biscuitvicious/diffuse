# diffuse — known bugs

Confirmed defects awaiting a fix, grouped by subsystem. Checked items are resolved.

## 1. Execution context and CLI

- [x] **Silent empty output when git fails to resolve the input range**: Running `diffuse -p <range>` (or any mode that shells out to `git diff`) with unknown revisions prints nothing — 4 bytes (`\x1b[0m`) on stdout, nothing on stderr — and exits 0. Repro: `diffuse -p f7fa5c3..9b06db9` outside the repository those commits belong to (e.g. submodule SHAs from the main repo); compare with `git diff f7fa5c3..9b06db9`, which correctly reports `fatal: ambiguous argument ... unknown revision or path not in the working tree`. Expected: surface git's stderr and exit non-zero instead of rendering an empty diff. (See **Use ariadne for CLI error reporting** in `TODO.md` §7.)
- [x] **Headless PTY / unresponsive terminal causes unhandled cursor query timeout**: When diffuse is invoked in an environment where `is_terminal()` returns true (such as a headless PTY or automated test runner without an active terminal emulator) and neither `--pager` nor `--no-tui` is specified, diffuse attempts to launch the interactive TUI. During `TerminalGuard::enter()`, Ratatui queries the hardware cursor position (`ESC [ 6 n`). Because no terminal emulator responds, Crossterm times out after 2 seconds with `The cursor position could not be read within a normal duration` and exits with an unhandled `io::Error`. Expected: `diffuse` should catch terminal initialization failure and gracefully fall back to the one-shot pager / CLI renderer instead of crashing.

## 2. Review notes

- [x] **`notes add` silently ignores `--diff` / `--old-dir` / `--new-dir`**: fixed by honouring file-based review input in the add flow. An explicit `--diff` file now always wins (even inside a work tree, mirroring diff-stream routing): `load_file_review` reads the patch plus the `--old-dir` / `--new-dir` snapshots for the target file (old-side lookup follows the diff's old path so renames resolve), runs the pipeline over the given diff with those maps, and anchors the note to the produced rows. Missing snapshot sides degrade exactly like a file missing from a git diff (banner note for new-side, informative `--old-dir` hint for old-side); a corrupt patch is refused with exit 2, matching non-interactive streaming. The snapshot dirs also feed the no-reviewed-diff fallback (new side only), so `--new-dir` helps even without `--diff`. Covered by `notes_add_honours_explicit_diff_and_snapshot_dirs_outside_repo`, which anchors new- and old-side notes outside a repo against snapshots while a cwd decoy proves the working tree is no longer read.

## 3. Diff parsing

- [x] **Over-claimed hunk header counts materialize blank separator lines as phantom context rows**: fixed by refusing corrupt input at parse time. `parse_diff_lines_with_raw` now verifies every hunk at close: a header claiming more or fewer lines than its body carries fails with `HunkCountMismatch` (via `thiserror`) instead of emitting rows. The count-growth lines (`hunk.old_count.max(...)`) are removed, so declared counts stay pristine and the blank-line gate runs on trusted extents. Well-formed hunks — including the tolerated stripped-whitespace blank context row inside an exactly-claimed extent — parse exactly as before. Callers: batch APIs return `Result`, `stream_diff_reader` reports the outcome on an error port surfaced by the CLI as `diffuse: corrupt diff: …` with exit 2, and batch/streaming entry points validate eagerly.
- [x] **Emitted hunk header counts inherit the malformed input header**: fixed as a consequence of the above — corrupt headers never reach the pipeline, so wire counts always describe the emitted rows. Additionally, `process_single_diff_file` carries a debug-only DbC invariant (`check_hunk_counts`) over programmatically materialized `DiffFile` values, and `OutputHunk::validate_invariants` continues to guard runs, text, and peer groups.

## 4. Collapse and peer groups

- [ ] **Moved rows cannot carry peer-group membership, so a formation justified by whole-row moves reads as unjustified**: `Row::MovSrc` / `Row::MovTgt` (`crates/diffuse-parse/src/row.rs`) have no `group` field, `Row::group()` reports `None` for them, and `set_group` is a no-op — even though slot alignment types them from grouped slots (`AlignedSlotRow.group`, `collapse/slot.rs`) and `collapse/peer.rs` computes `peer_group_meta` for those slots before discarding it. `recalibrate_peer_groups` therefore tests "witnesses relocated text" (`fragment_formation`) only over the group-tagged members, which for whole-row relocations carry no moved runs; the formation dissolves and `pass_normalize_identical_mods` re-clusters the orphaned rows, turning a real move into plain `Del`/`Add` rows plus spurious long-range `Ctx` pairings. Observed in `diffcoord-anchoring` (`crates/diffuse-core/src/notes.rs`, hunk at old line 400): old 435–437 (`Self(unsafe { NonZero::new_unchecked(val) })`, `    }`, blank) previously rendered as `mov` ↔ new 558–560; after the recalibration change they render as `del` 435 plus `ctx` 436↔480 and 437↔491 plus three plain `add`s. Expected: `MovSrc`/`MovTgt` carry `Option<PeerGroup>` like `Del`/`Add`; `g` survives `OutputRow::reconstruct()` for `k: "mov"`; and recalibration, `check_peer_token_conservation` and `Hunk::validate_reflow_groups` account for the group's moved members. Rendering needs a matching decision first: `styled_prefix_spans_with_widths` sends a grouped `RowKind::Mov` through its `_` arm (a context gutter, dropping both `≈` and the change sign), and the group marker `~` and move glyph `≈` compete for the same gutter column, so a third column is required.
